# Локальный запуск всего проекта

Эта инструкция предназначена для первого запуска на компьютере разработчика. Есть два режима:

- **Демонстрационный** — работает без сервера и базы. Используйте его для знакомства с интерфейсами и проверки админки.
- **С реальными локальными данными** — запускает backend и отдельную PostgreSQL 18 без моков.

Не смешивайте режимы в одном запуске. Не вводите настоящие персональные данные в демонстрационный режим.

## Что установить заранее

1. Node.js 24.22.1.
2. npm 11.
3. Для режима с реальными данными — PostgreSQL 18 для Windows. Во время установки можно не создавать отдельную рабочую базу: проект создаст свой изолированный набор данных.
4. Убедитесь, что порты 3000, 3001, 3002 и 54329 свободны.

## Вариант 1. Быстрый демонстрационный запуск

Backend и база для этого варианта не нужны.

### Основное приложение

Откройте PowerShell и выполните:

```powershell
Set-Location 'D:\Agents\EP Frontend projects\projects\test-roject\meal_frontend'
npm ci
$env:NEXT_PUBLIC_API_MODE='mock'
$env:NEXT_PUBLIC_LEGAL_EVIDENCE_MODE='demonstration'
npm run dev
```

Оставьте окно открытым. Основное приложение будет доступно по адресу `http://localhost:3000`.

### Админка

Откройте второе окно PowerShell и выполните:

```powershell
Set-Location 'D:\Agents\EP Frontend projects\projects\test-roject\meal_admin'
npm ci
$env:VITE_API_MODE='mock'
npm run dev
```

Оставьте окно открытым. Админка будет доступна по адресу `http://localhost:3002`.

Для первого входа используйте логин `admin` и пароль `1`. Полная последовательность описана в `meal_admin/docs/ADMIN_GUIDE.md`.

### Как остановить

В каждом открытом окне PowerShell нажмите `Ctrl+C`. Данные демонстрационного режима сохраняются только в браузере.

## Вариант 2. Полноценный запуск без моков

Этот вариант создаёт отдельную постоянную development-базу в `meal_backend/.local/postgres`. Она не затрагивает системную базу PostgreSQL, не удаляется при остановке и не используется в production. Скрипт никогда не перезаписывает уже созданную базу.

### Шаг 1. Установите зависимости трёх частей

По очереди выполните в PowerShell:

```powershell
Set-Location 'D:\Agents\EP Frontend projects\projects\test-roject\meal_backend'
npm ci

Set-Location 'D:\Agents\EP Frontend projects\projects\test-roject\meal_frontend'
npm ci

Set-Location 'D:\Agents\EP Frontend projects\projects\test-roject\meal_admin'
npm ci
```

Эти команды нужны только после первого скачивания проекта или изменения зависимостей.

### Шаг 2. Посмотрите план создания базы

Вернитесь в папку backend:

```powershell
Set-Location 'D:\Agents\EP Frontend projects\projects\test-roject\meal_backend'
npm run local:db:plan
```

Команда показывает будущие действия, но ничего не создаёт и не меняет.

### Шаг 3. Создайте базу

У обычной установки PostgreSQL 18 нужная папка находится здесь: `C:\Program Files\PostgreSQL\18\bin`. Если PostgreSQL установлен в другое место, укажите свою папку `bin`.

```powershell
npm run local:db:create -- -PgBin 'C:\Program Files\PostgreSQL\18\bin'
```

Скрипт автоматически:

1. создаст отдельный PostgreSQL на `127.0.0.1:54329`;
2. создаст базу `meal_planner_postgres`;
3. применит все 42 миграции и системные справочники;
4. создаст отдельного пользователя с минимальными правами для приложения;
5. сгенерирует случайные локальные ключи;
6. сохранит настройки в закрытой папке `meal_backend/.local`;
7. проверит версию схемы, справочники и права подключения.

Пароли и ключи не выводятся в консоль и не должны попадать в Git. Если создание прервалось, скрипт оставит частичные данные для диагностики и не станет удалять их автоматически.

Проверьте состояние:

```powershell
npm run local:db:status
```

Успешный результат сообщает, что база запущена и применены 42 миграции.

### Шаг 4. Запустите весь проект одной командой

```powershell
npm run local:real
```

Команда сама:

- запустит ранее созданную базу, если она была остановлена;
- соберёт и запустит backend;
- запустит основное приложение и админку строго без моков;
- дождётся готовности всех трёх частей;
- выполнит безопасную проверку связи между интерфейсами, backend и базой.

После сообщения об успешном запуске доступны:

- основное приложение — `http://localhost:3000`;
- админка — `http://localhost:3002`;
- состояние backend и базы — `http://127.0.0.1:3001/health/ready`.

Если нужна только предварительная проверка файлов, версий и свободных портов без запуска:

```powershell
npm run local:real:check
```

### Шаг 5. Создайте первого администратора

Следуйте `meal_backend/docs/FIRST_ADMIN.md`. Сначала аккаунт `admin` регистрируется через основное приложение и подтверждает почту, затем безопасная backend-команда назначает ему роль.

### Шаг 6. Проверьте админку

1. Войдите в `http://localhost:3002/auth` под созданным администратором.
2. Завершите настройку приложения-аутентификатора и сохраните резервные коды.
3. Откройте «Система → Тестирование».
4. Начните с проверок, которые экран помечает как готовые к запуску.

На чистой базе сразу доступна основная проверка регистрации, входа, API и админки. Полный каталог из 83 сценариев потребует дополнительных тестовых пользователей и данных, указанных на самом экране. Внешние почтовые, платёжные, файловые и AI-провайдеры без настоящих ключей остаются безопасно выключенными.

## Как остановить и снова запустить

Нажмите `Ctrl+C` в окне `npm run local:real`. Backend, основное приложение и админка остановятся. База продолжит работать, а все тестовые данные сохранятся.

Чтобы остановить и базу:

```powershell
npm run local:db:stop
```

Чтобы продолжить работу в другой день, снова выполните `npm run local:real`. Повторно создавать базу не нужно.

Для серверного развёртывания используйте отдельный документ `docs/DEPLOYMENT.md`. Серверный Compose не предназначен для обычного локального запуска.
