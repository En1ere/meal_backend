# Web Push runbook

Web Push is disabled by default. The public contact is `mailto:saix789@gmail.com`; it is not a sender mailbox. The accepted default policy is quiet hours `22:00–08:00` in the user's timezone and TTL `300/14400/86400/21600` seconds for critical/important/informational/marketing delivery. Security/payment critical events bypass quiet hours; food risk does so only after explicit opt-in.

Generate one VAPID pair with `web-push generate-vapid-keys`, store only the public key in root-owned `deploy.env`, and store the private key in `/etc/meal-planner/secrets/web-push-vapid-private-key`. Generate an independent 32-byte base64 AES key in `web-push-subscription-key`. Both files are `root:meal-secrets 0640`; neither value is committed or returned by admin API. Run `deploy/provision-web-push-runtime.sh` after migration 034 to create the least-privilege database identity and URL secret.

Set `WEB_PUSH_ENABLED=true`, `WEB_PUSH_VAPID_SUBJECT=mailto:saix789@gmail.com` and the public key in `deploy.env`, then run `stack.sh up` and `verify.sh --component all`. The optional worker has DB+egress only, no ingress, read-only rootfs, dropped capabilities and bounded memory/CPU/PID. Browser subscriptions are session-bound, encrypted with AES-256-GCM and represented only by id/version to the client. Enqueue, claim and the instant before provider send independently require an active, unsanctioned user and live linked session; marketing additionally requires the latest marketing consent to be accepted. A 404/410 revokes the exact subscription. Only 429/5xx use bounded backoff and a safe `Retry-After` up to one hour; definite other 4xx are terminal, while an ambiguous/network outcome becomes terminal `unknown` without blind retry.

Disable by setting `WEB_PUSH_ENABLED=false` and running `stack.sh up`; the deployment scripts explicitly stop and remove the old `push-worker` through the Web Push overlay and verification rejects a leftover container. Migration 034 stays additive. Rotating either private key requires disabling delivery, revoking existing subscriptions for the encryption key rotation, installing new root-owned files and subscribing devices again.

Admin `/admin/runtime-settings` exposes only safe status, source, blockers, fingerprint and rotation metadata. Policy edits require an unlocked admin, fresh critical confirmation, preview, exact version and idempotent execution. Other registry entries remain read-only until a dedicated safe mutation contract exists.
