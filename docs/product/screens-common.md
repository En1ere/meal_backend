# 24. Карта экранов

<!-- /migration:source-1395 -->

<a id="source-1397"></a>
<!-- migration:source-1397 -->

Маршруты ниже являются канонической информационной архитектурой web/PWA. Параметры `:id`, `:username` и query-параметры не являются пользовательскими данными сами по себе; доступ к содержимому всегда повторно проверяет backend. Диалоги подтверждения, таймер, фильтры и короткие формы не получают отдельный URL, если им не требуется восстановление после reload или прямая ссылка.

<a id="248-готовность-карты-к-реализации"></a>

## 24.8. Готовность карты к реализации

<!-- /migration:source-2062 -->

<a id="source-2064"></a>
<!-- migration:source-2064 -->

Наличие маршрута означает утверждённую информационную архитектуру, но не готовность backend. Используются состояния `runtime-ready`, `contract-only`, `specified-no-contract`, `feature-flagged` и `blocked-by-open-question`.
<!-- /migration:source-2064 -->

<a id="source-2079"></a>
<!-- migration:source-2079 -->

Целевой wireframe разрешён для любого утверждённого маршрута, но production-реализация начинается только после требуемого контракта и mock runtime.

<a id="249-общие-состояния-и-адаптивность"></a>

## 24.9. Общие состояния и адаптивность

<!-- /migration:source-2081 -->

<a id="source-2083"></a>
<!-- migration:source-2083 -->

Каждая страница проектируется минимум в состояниях `loading`, `ready`, `empty`, `error`, `forbidden` и `not-found`. Изменяющие формы дополнительно имеют `dirty`, `validating`, `submitting`, `success`, `conflict`, `rate-limited` и `retryable/non-retryable failure`. Тарифное ограничение, истёкший entitlement и отсутствие данных — разные состояния.
<!-- /migration:source-2083 -->

<a id="source-2085"></a>
<!-- migration:source-2085 -->

Offline capability задаётся маршрутом и действием: `offline-readable` для заранее загруженных разрешённых данных, `offline-queueable` только для операций §18/§28.12 и `online-required` для auth/MFA, платежей, AI, публикации, модерации, admin и требующих актуального сервера действий. Online-required действие без сети не показывается успешным и не попадает в ложную очередь выполнения.
<!-- /migration:source-2085 -->

<a id="source-2087"></a>
<!-- migration:source-2087 -->

Protected deep link без подходящей сессии переводит на соответствующий user/moderator/admin sign-in с `returnTo`, содержащим только внутренний нормализованный путь разрешённого origin. External URL, служебные пути другого контура и malformed значения отвергаются. После sign-in/MFA/reauth backend повторно проверяет роль, grant, тариф и scope. Expired/revoked/downgraded состояние после reload очищает защищённый кэш и ведёт к безопасному session/access screen, сохраняя только допустимый `returnTo`.
<!-- /migration:source-2087 -->

<a id="source-2089"></a>
<!-- migration:source-2089 -->

Динамические сегменты валидируются до загрузки: `:id` — UUID, `:document` и `:queue` — allowlist, `:username` — нормализованный percent-decoded slug, invitation `:token` — opaque one-time value. Malformed/unknown даёт `404`; существующий недоступный объект — безопасный `403` или `404` по anti-enumeration policy. Alias старого product/recipe ID разрешается только backend после authorization и ведёт canonical redirect с безопасными query-параметрами; удалённый без alias ресурс возвращает `410` лишь там, где это не раскрывает его существование.
<!-- /migration:source-2089 -->

<a id="source-2091"></a>
<!-- migration:source-2091 -->

Desktop использует устойчивую боковую/верхнюю навигацию, split-view только там, где список и detail остаются понятны независимо. Mobile использует нижнюю навигацию для главных разделов, drill-down для detail, bottom sheet/fullscreen dialog для сложных действий и зоны нажатия не менее 44 px. Таблица на mobile превращается в содержательные карточки, а не в горизонтально обрезанный desktop. Приготовление, таймер, чек/OCR, семейный чат и критичные подтверждения проектируются mobile-first; все остальные страницы всё равно обязаны иметь проверенный mobile-вариант.
<!-- /migration:source-2091 -->

<a id="source-2093"></a>
<!-- migration:source-2093 -->

Категории настроек, способные содержать длинный или расширяемый набор значений — предпочтения, антипатии, аллергены, техника, немедицинские цели и аналогичные multi-select — не раскрываются inline. Страница показывает компактный summary из первых выбранных значений и индикатор `+N ещё`; полное редактирование открывается в selector surface: центрированный скруглённый modal dialog с backdrop на desktop и modal bottom sheet на mobile. Внутри предусмотрены заголовок, поиск при большом каталоге, прокручиваемый список, отображение выбранного и явные `Отмена`/`Применить`. Небольшие конечные наборы сохраняют inline switch/radio/checkbox. Accordion используется для disclosure содержимого, но не заменяет selector.
<!-- /migration:source-2093 -->

<a id="source-2095"></a>
<!-- migration:source-2095 -->

Техника обязана различать `Есть`, `Нет` и `Не указано`; немедицинские цели допускают множественный выбор. Применение внутри selector обновляет черновик страницы, но окончательно сохраняет его только общее действие формы. Selector обеспечивает focus trap, Escape/scrim-close с защитой несохранённых изменений, возврат фокуса на исходный summary, доступные selected/checked states и sticky actions без перекрытия контента. Окончательный визуальный язык dialog/bottom sheet определяется при проектировании UI-kit; текущие макеты фиксируют interaction contract.
<!-- /migration:source-2095 -->

<a id="source-2097"></a>
<!-- migration:source-2097 -->

Глобальная навигация в пределах одного приложения и viewport имеет единый состав, порядок, названия и иконографику; переход между страницами меняет active-state, но не подменяет пункты меню. Любое изменение app shell сначала принимается как общее решение и затем синхронно отражается во всех затронутых макетах, документации и реализации.
<!-- /migration:source-2097 -->

<a id="source-2099"></a>
<!-- migration:source-2099 -->

Канонический визуальный реестр иконок согласованных макетов хранится в `UI/icons.png`. В нём одинаковые glyph не дублируются, каждая иконка подписана, различающиеся ранние варианты явно отмечены, а значимые состояния показаны отдельно. Добавление, изменение или удаление иконки в макете в той же итерации синхронизирует реестр; перед завершением он сверяется со всеми выбранными `UI/**/*_selected.*`. Реестр служит дизайн-источником для будущего UI-kit и не является самостоятельным API-контрактом компонентов.
<!-- /migration:source-2099 -->

<a id="source-2101"></a>
<!-- migration:source-2101 -->

Канонический desktop sidebar использует реальные top-level маршруты в неизменном порядке: `Дом` (`/`), `Запасы` (`/inventory`), `Рецепты` (`/recipes`), `План` (`/plan`), `Покупки` (`/shopping`), `Семья` (`/family`, с честной отметкой Plus при необходимости), `Сообщество` (`/community`), `Профиль` (`/profile`) и `Настройки` (`/settings`). Допустимы только визуальные группы `Планирование`, `Вместе`, `Аккаунт`; они не меняют маршруты. Search, notifications и avatar остаются utilities верхней панели. Sidebar имеет доступную кнопку сворачивания/разворачивания; collapsed-состояние сохраняет порядок иконок, active-state, keyboard focus и доступные tooltip/labels.
<!-- /migration:source-2101 -->

<a id="source-2103"></a>
<!-- migration:source-2103 -->

Каноническая mobile bottom navigation использует пять постоянных позиций: `Дом`, `Запасы`, `Рецепты`, `План`, `Ещё`. Активная позиция получает primary-заливку с белыми иконкой и текстом, а состояние дополнительно обозначается формой/начертанием. `Ещё` открывает modal bottom sheet с остальной навигацией: `Покупки`, `Семья`, `Сообщество`, `AI-помощник`; role-aware группа Pro (`Обзор Pro`, `Дневник`, `Финансы`); `Профиль`, `Достижения`, `Уведомления`, `Настройки`; `Новости`, `Поддержка`. Детальные CRUD-маршруты в меню не дублируются: активируется ближайший родитель. Если текущий маршрут находится внутри `Ещё`, активны кнопка `Ещё` и соответствующая строка sheet. Sheet поддерживает focus trap, закрытие Escape/back/scrim, возврат фокуса и закрытие после успешной навигации; открытие и закрытие само по себе не меняет маршрут.
<!-- /migration:source-2103 -->
