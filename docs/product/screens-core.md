Согласованная композиция `/inventory`: desktop использует компактный табличный реестр и небольшую горизонтальную плашку о партиях с близким сроком годности; mobile группирует партии по выбранному месту хранения и показывает компактную кнопку `Требует внимания · N` только при `N > 0`. Плашка и кнопка открывают отфильтрованный список требующих внимания партий, не скрывают остальные запасы и не смешивают private scope с семейным. Значение `N` вычисляется из доступных пользователю партий по тому же правилу срочности, что и фильтр списка; при частичной ошибке или неизвестном результате число не подменяется нулём.

<a id="source-1456"></a>
<!-- migration:source-1456 -->

Для `/inventory/new` runtime-ready путь начинается с поиска и выбора существующего `Ingredient`, затем явного выбора `private|family` scope, доступного в этом scope места хранения и параметров партии. Обязательны продукт, место, положительное decimal-количество и поддерживаемая единица; точность показывается пользователю как `Точно|Примерно`. Состояние упаковки в форме задаётся двухпозиционным переключателем `Закрыто|Открыто`, а не dropdown: выбор переводится в `sealed|opened`, при `Открыто` становится доступна дата открытия. Пока пользователь не сделал явный выбор, контрактное `unknown` сохраняется и не подменяется `Закрыто`. Неизвестные даты, цена, магазин, штрихкод и состояние не подменяются нулями. При смене scope несовместимое место очищается и загружается новый scope-ограниченный список. Создание нового каталожного товара остаётся отдельным проверяемым сценарием и не считается выполненным вместе с созданием партии. Offline-интерфейс не показывает server success и не обещает очередь до реализации соответствующего контракта.

<a id="source-1461"></a>
<!-- migration:source-1461 -->

Импорт запасов принимает `CSV`, `TSV`, `XLSX` и `ODS`. CSV/TSV считаются одним виртуальным листом; для XLSX/ODS пользователь явно выбирает один или несколько листов и строку заголовков каждого. Сопоставление хранится по устойчивой идентичности листа и индексу колонки; перенос mapping между листами разрешён только после подтверждения одинаковых нормализованных заголовков. Каждая строка review сохраняет происхождение `лист + номер строки`. Scope един для одной операции импорта; разные private/family назначения требуют отдельных импортов.
<!-- /migration:source-1461 -->

<a id="source-1463"></a>
<!-- migration:source-1463 -->

Формулы, макросы, скрипты, внешние подключения, embedded objects и ссылки не выполняются. Formula cells помечаются как недоверенные и требуют предусмотренного будущим контрактом review; значения, начинающиеся с `=`, `+`, `-`, `@`, не интерпретируются как команды. XLSX/ODS разбираются изолированно без внешних запросов и XML external entities. Лимиты размера файла, распакованного объёма, листов, строк, колонок и времени разбора задаются версионированной конфигурацией, а не зашиваются в макет. Прямой Google Sheets import не заявлен: пользователь скачивает таблицу в поддерживаемом формате. Legacy `XLS` остаётся неподдержанным до выбора безопасного parser contract.

| `/inventory/history` | История реестра | Фильтровать поступления, расход, готовку, перемещения, корректировки и компенсации | По scope |

История запасов использует `effective_at` как основное пользовательское время; если `recorded_at` заметно позже, событие помечается «Записано позже». Private и family scope не объединяются в один результат. Обзор не предоставляет редактирование журнала, массовый откат или экспорт без отдельного контракта. На mobile строка открывает отдельный detail-screen, а не inline accordion.

<a id="source-1472"></a>

Экран синхронизации показывает локальную очередь даже во время отправки и различает состояние иконкой, текстом и цветом. Он не заявляет резервное копирование или абсолютную сохранность данных и не показывает фиктивный процент без серверного progress. Private и family queue изолированы; family-доступ повторно проверяется сервером. При конфликте локальный ввод остаётся доступен до решения. Для остатков и денег нельзя применять слепое «оставить моё»: пользователь либо подтверждает фактическое текущее значение через предусмотренный flow, либо принимает серверную версию. Закрытие detail не удаляет конфликт. Mobile открывает конфликт отдельным экраном, не accordion.

При `412 VERSION_CONFLICT` форма и ввод сохраняются, загружается свежая версия для сравнения; слепого overwrite нет.

Карточка продукта разделяет публичные каталожные данные и приватные запасы пользователя. Иерархия каталога: базовый ингредиент → вариант → конкретный SKU/фасовка; barcode и данные упаковки относятся только к SKU. Неизвестные КБЖУ, состав или allergens показываются как «Нет данных»/«Неизвестно», а не как нулевые или безопасные значения. Если для выбранного продукта известны allergens, desktop показывает рядом с основными каталожными сведениями самостоятельную контрастную плашку `Содержит аллерген: …`; при отсутствии подтверждённых данных плашка не отображается и интерфейс не заявляет безопасность. Личные партии выводятся отдельным блоком и могут загружаться по `ingredient_id`; семейные партии запрашиваются отдельным scope только после проверки доступа. Экран не обещает отзывы, health score, сравнение цен, ручное редактирование общего каталога или объединение товаров без соответствующих контрактов. До реализации `/products/:id` нужны typed detail query, DTO для variant/SKU и provenance.

Корень `/preserves` показывает только личные заготовки; семейная коллекция открывается отдельным маршрутом `/family/preserves` после проверки активного членства и тарифа семейного покрытия. Список поддерживает поиск и фильтры по типу, месту, известному сроку и архивному состоянию. Неизвестный срок обозначается `Срок не указан` и не считается безопасным; прошедшая дата формулируется как `Срок прошёл — проверьте продукт`, без автоматического вывода о порче. Attention-entry отображается только при `N > 0` по известным датам. Создание доступно Free+, а QR/печатный файл остаются Plus/Pro-возможностями detail-экрана и не повторяются как действие каждой строки списка. Группировка по месяцу может вычисляться из `created_at` только для отображения и не создаёт новую сущность сезона.

`Использовать` открывает отдельную форму количества и единицы с preview остатка и не списывает данные одним нажатием. QR и печатный файл доступны Plus/Pro после entitlement-проверки: QR содержит только минимальные идентифицирующие сведения, а открытие карточки всё равно проверяет auth и scope; печать использует системный диалог без выбора конкретной модели принтера.

Продолжение той же беседы тарифицируется по §16.2 без повторного preview и показа стоимости. Смена цели создаёт новую задачу. Повторное открытие сохранённого результата бесплатно и не создаёт новую операцию.
