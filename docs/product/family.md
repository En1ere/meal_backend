Действующее семейное покрытие Plus/Pro (§4.1 ниже) включает до 4 аккаунтов суммарно, включая владельца. Владелец может купить максимум два постоянных расширения по 399 ₽ разово: каждое добавляет +4 места, итоговые лимиты — 8 и 12 аккаунтов. Право на места закрепляется за аккаунтом владельца, не требует повторной оплаты и действует при активном семейном покрытии, открывающем семью; без активного Plus/Pro семейный функционал блокируется, но купленные места сохраняются. При подтверждённой передаче владения оплаченные семейные слоты передаются новому владельцу вместе с семьёй и перестают принадлежать прежнему владельцу; preview показывает состав, слоты и последствия. Профили без аккаунта в лимит не входят. Расширение не увеличивает общий AI-лимит семьи; это явно показывается до оплаты.

Возврат запрашивает плательщик в пределах закона и правил платёжного провайдера; до подтверждения возврата показывать влияние на вместимость семьи и не удалять участников молча.

### Семейное покрытие после решения MP-05

<!-- /migration:source-259 -->

<a id="source-261"></a>
<!-- migration:source-261 -->

Покрытие семьи определяется явно связанной подпиской: обычный Plus/Pro владельца либо Pro, полученный объединением двух Plus участников этой семьи и закреплённый за выбранным аккаунтом. При потере текущего покрытия автоматически использовать другую действующую подписку, подходящую для этой семьи по §4.1; не складывать квоты и не менять настройки оплаты.

Дополнительные права владельца ограничены управлением участниками. Владение не даёт отдельного права скрывать чужие заметки, откатывать чужие бытовые действия или читать личные данные. Авторские права на текст/архивирование своих заметок сохраняются; скрытие чужого материала — только у себя, пакетный откат — только своих действий после проверки последствий; отдельной команды архивации действующей семьи нет (MP-01).
<!-- /migration:source-281 -->

<a id="source-283"></a>
<!-- migration:source-283 -->

При выходе владельца, если остаются другие участники с аккаунтами, показывается модалка «Кому передать владение?» с выбором участника и кнопкой «Всё равно». По кнопке «Всё равно» преемник назначается автоматически, без дополнительных подтверждений и без ожидания согласия нового владельца. Выбирается действующий участник с самым длительным непрерывным пребыванием в семье, считая с последнего вступления. При равном стаже используется стабильный порядок списка участников; если старейшего определить невозможно, выбирается следующий по этому списку. Выходящего и профили без аккаунта не выбирать. Назначенному владельцу отправляется уведомление; при следующем входе показывается важная полноэкранная модалка по паттерну §28.10 с одной кнопкой закрытия. Она сообщает об уже состоявшемся назначении: закрытие не является согласием и не влияет на владение. Выход и передача завершаются согласованно, без активной семьи без владельца. Если выходит последний участник с аккаунтом, семья архивируется с сохранением данных; преемника нет, передача не требуется. Добровольная передача без выхода сохраняет двухстороннее принятие; прежний владелец в этом случае остаётся участником.

<a id="44-приватность-семьи"></a>

## 4.4. Приватность семьи

<!-- /migration:source-307 -->

<a id="source-309"></a>
<!-- migration:source-309 -->

Личные и семейные данные и операции строго разделены. Перед действием явно выбрана область «Личные» или «Семья»: списание, поступление, покупки, планирование, стоимость, отчёт, экспорт и AI-контекст используют только разрешённые источники этой области. Нехватка в одной области не компенсируется автоматически другой. Переключение не переносит записи и не повторяет операции; несохранённый ввод требует сохранения либо явного отказа. Вкладки «Семья»/«Личные» приняты; семейная вкладка — default при членстве. Переключатель «Семья / Личные» единый для запасов, покупок, рецептов, планов и финансов. Выбранная область сохраняется при переходах между этими разделами; каждый раздел не требует нового выбора. При новом входе пользователя, состоящего в семье, снова открывается «Семья». Без семьи используется личная область. Переключение не меняет область существующих записей и начатых операций; личный дневник сохраняет приватность. Личный дневник не становится видимым семье из-за семейного источника еды; семейная порция отражается в личном дневнике по отдельному согласованному сценарию §28.9 с автоподтверждением через 24 часа и поздней отменой. Это не перенос семейных запасов в личные.
<!-- /migration:source-309 -->

<a id="source-311"></a>
<!-- migration:source-311 -->

- Если пользователь состоит в семье, при входе без явно выбранного личного контекста всегда открывается вкладка «Семья». Все операции, поддерживающие личную и семейную области, по умолчанию семейные: запасы, покупки, чеки, рецепты и их черновики, планы, заготовки, финансовый учёт, экспорт и AI-контекст. «Личные» — дополнительный режим, включаемый явно; в нём операции остаются личными. Последний личный выбор не становится новым default при следующем входе. Без семьи используется личная область. Область видна до подтверждения и закрепляется за начатой операцией: default не переназначает открытый черновик, существующую запись или очередь. При недоступной семье показать причину и возможность явно выбрать личный режим, без скрытого переключения. Семейный default не раскрывает личный дневник и существующие приватные данные; учёт семейной порции в личном дневнике подчиняется §28.9.
- Прежние настройки предпочтительной области по типам данных не переопределяют семейный default. Пользователь может явно выбрать личную область для нужной работы; проверки членства, прав и изоляции сохраняются.
- Покупки, чеки и финансы следуют общему семейному default; прежний режим `private | family | ask` не задаёт иной default. Личный дневник сохраняет свою приватность. Публичность не является третьим глобальным значением: публикация доступна только поддерживающим её сущностям через отдельное явное действие.
- При создании пользователь может изменить предложенную видимость на `private` или `family`, если у него есть соответствующее право.
- Личные финансы и дневник видит только их владелец. Отдельную покупку можно явно сделать семейной или поделиться выбранным набором; владелец семьи не может открыть семье чужую личную финансовую историю.
- При выходе из семьи семейные данные остаются в семье; приватные данные пользователя не передаются семье.
- Вышедший пользователь сохраняется как архивный участник для целостности истории; его можно восстановить повторным приглашением.
- Архивирование семьи сохраняет историю и записи участников. При выходе последнего участника с аккаунтом оно выполняется автоматически по MP-04; отдельная команда архивирования действующей семьи отсутствует. Окончательное физическое уничтожение — отдельный подтверждаемый сценарий после юридической проверки; окончание подписки данные не удаляет.

<a id="283-семья-подписка-и-жизненный-цикл"></a>

## 28.3. Семья, подписка и жизненный цикл

<!-- /migration:source-2224 -->

<a id="source-2226"></a>
<!-- migration:source-2226 -->

- Одна активная семья на аккаунт. Владелец, плательщик и получатель подписки — разные роли. Участник может подготовить приглашение, владелец подтверждает/отказывает, приглашённый принимает. Добровольная передача без выхода требует принятия; выход владельца подчиняется выбору преемника / «Всё равно», а выход последнего участника — архивированию по §4.2. Любой участник может запросить смену владельца через поддержку.
- Действующее семейное покрытие Plus/Pro покрывает суммарно 4 аккаунта, включая владельца. Можно разово купить до двух постоянных расширений по 399 ₽; каждое добавляет +4 места, итоговые лимиты — 8 и 12. При подтверждённой передаче владения оплаченные семейные слоты переходят новому владельцу вместе с семьёй и больше не принадлежат прежнему; preflight показывает состав, лимит и последствия. Профили без аккаунта места не занимают. Расширение не увеличивает общий AI-лимит семьи; это показывается до оплаты.
- Другой человек может оплатить расширение как подарок владельцу: владелец принимает его до активации, право получает владелец, платёжный документ и право запросить возврат в пределах закона остаются у плательщика. Выход плательщика не отзывает места; возможный возврат предварительно показывает влияние на вместимость и никого не удаляет молча.
- Профиль без аккаунта, включая ребёнка, не имеет входа; при регистрации связывается после подтверждения без потери истории и настроек. Вышедший участник архивируется; его можно скрыть из интерфейса, но историческое авторство остаётся.
- Семья и чат доступны по явно связанному покрытию (§4.1): по умолчанию Plus/Pro владельца, либо объединённый Pro выбранного участника; тариф и AI-лимиты определяются этим покрытием. Другой участник может выступить плательщиком, но получателем покупки должен быть явно указан владелец; обычная личная подписка участника сама по себе семью не покрывает; исключение — явно связанный объединённый Pro по MP-05, квоты не суммируются. До создания семьи в trial и в заголовке семейного раздела показывать дату окончания trial и прямо объяснять последующую блокировку. После оплаченного периода действует страховка 3 дня; поддержка может добавить ещё 7 дней один раз на подтверждённый платёжный инцидент с причиной и аудитом. Затем весь семейный UI, чтение истории, чат, корректировки и завершение старых семейных сценариев блокируются; членство/данные сохраняются. Даже при блокировке доступны экран состояния подписки, состав семьи без содержимого данных, экспорт, выход, передача владения и поддержка. Восстановление действующего семейного покрытия возвращает доступ всем без повторных приглашений. Перед оплатой показать семью и получателя; устаревшие остатки/планы предложить проверить, пропущенные автоматизации не запускать молча.
- Выход, обращение в поддержку и передача владения доступны без подписки. При выходе владельца, если остаются другие участники с аккаунтами, показывается модалка «Кому передать владение?» с выбором участника и кнопкой «Всё равно». По кнопке «Всё равно» преемник назначается автоматически, без дополнительных подтверждений и без ожидания согласия нового владельца. Выбирается действующий участник с самым длительным непрерывным пребыванием в семье, считая с последнего вступления. При равном стаже используется стабильный порядок списка участников; если старейшего определить невозможно, выбирается следующий по этому списку. Выходящего и профили без аккаунта не выбирать. Назначенному владельцу отправляется уведомление; при следующем входе показывается важная полноэкранная модалка по паттерну §28.10 с одной кнопкой закрытия. Она сообщает об уже состоявшемся назначении: закрытие не является согласием и не влияет на владение. Выход и передача завершаются согласованно, без активной семьи без владельца. Если выходит последний участник с аккаунтом, семья архивируется с сохранением данных; преемника нет, передача не требуется. Добровольная передача без выхода сохраняет двухстороннее принятие; прежний владелец в этом случае остаётся участником. Общие запасы при выходе автоматически не делятся; планы, порции, резервы и поручения пересматриваются явно.
- Все участники корректируют общие бытовые данные. Автор может отменить своё последнее обратимое действие, пока оно не заблокировано зависимостями; последствия показываются до подтверждения. Пакетный откат разрешён каждому участнику только для своих обратимых действий, с preview последствий и зависимостей; набор применяется целиком либо никак. Владелец не может откатывать чужие события по своей роли. Сильное противоречие разрешается формой «Что есть сейчас» как новой компенсирующей корректировкой.
- Область операций по умолчанию — семья при членстве; личная работа включается явно. Применять §4.4 ко всем поддерживающим обе области операциям, без переноса существующих данных и без подмены области начатой операции.
- Владение семьёй не даёт особого права скрыть материал для всех. Чужой общий материал можно скрыть только из своего интерфейса: история, личные материалы и фактический состав общей еды не меняются (MP-01).

Уточнение прав (History 868–869): MP-01: каждый участник может скрыть чужую общую запись только из собственного интерфейса, без удаления для семьи и изменения общих итогов. Экспорт семейных данных доступен любому действующему участнику без чужих личных данных. Семья архивируется автоматически при выходе последнего участника с аккаунтом; отдельной команды архивирования действующей семьи нет.
