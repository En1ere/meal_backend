## 18.1. Офлайн-возможности в общем MVP

<!-- /migration:source-1102 -->

<a id="source-1104"></a>
<!-- migration:source-1104 -->

Без сети поддержать:
<!-- /migration:source-1104 -->

<a id="source-1106"></a>
<!-- migration:source-1106 -->

- пошаговое приготовление и таймеры;
- два последних открытых рецепта;
- личный дневник Pro;
- ручное добавление покупок;
- создание, редактирование и архивирование личных рецептов; окончательное удаление только неопубликованных черновиков по retention-процедуре.

<!-- /migration:source-1106 -->

<a id="source-1112"></a>
<!-- migration:source-1112 -->

Изменения сохраняются локально и отправляются автоматически после появления сети. Офлайн можно архивировать личный рецепт или поставить `request_delete`/tombstone для неопубликованного черновика; физическое удаление подтверждается только сервером после синхронизации и проверки retention. Снятие публикации и удаление опубликованных данных требуют сервера.
<!-- /migration:source-1112 -->

<a id="source-1114"></a>
<!-- migration:source-1114 -->

Все перечисленные возможности входят в общий MVP, который выпускается последовательно Free -> Plus -> Pro. Функция становится доступна офлайн не раньше тарифной итерации, в которой появляется её основной онлайн-сценарий. Платежи, AI, публикация, модерация и другие действия, требующие актуального серверного решения, офлайн не считаются завершёнными.
<!-- /migration:source-1114 -->

<a id="source-1118"></a>

## 18.3. Очередь операций

<!-- /migration:source-1122 -->

<a id="source-1124"></a>
<!-- migration:source-1124 -->

Основной принцип: подтверждённые локальные действия должны быть восстанавливаемыми и не должны молча исчезать. Измеримые гарантии задаются через durability, RPO/RTO, идемпотентность, резервные копии и тесты восстановления; абсолютная гарантия отсутствия потерь не заявляется.
<!-- /migration:source-1124 -->

<a id="source-1126"></a>
<!-- migration:source-1126 -->

```json
{
    "queue_id": "uuid",
    "operation_type": "create|update|archive|restore|request_delete|unpublish",
    "entity_type": "product|recipe|purchase|diary|...",
    "entity_id": "uuid",
    "data": {},
    "base_version": "number|null",
    "idempotency_key": "string",
    "depends_on": ["queue_id"],
    "created_at": "timestamp",
    "status": "pending|synced|failed|conflict|rejected|auth_required|superseded",
    "retry_count": 0,
    "server_revision": "string|null"
}
```

<!-- /migration:source-1126 -->

<a id="source-1143"></a>
<!-- migration:source-1143 -->

Автоматически синхронизировать очередь при восстановлении сети. Показывать количество ожидающих операций. Приоритет: покупки и сроки, затем реестр и рецепты, затем комментарии и реакции.

<a id="184-конфликты"></a>

## 18.4. Конфликты

<!-- /migration:source-1145 -->

<a id="source-1147"></a>
<!-- migration:source-1147 -->

- Первое правило: для безопасных независимых полей сервер сравнивает `base_version` с текущей серверной ревизией/ETag; клиентский timestamp используется только для отображения и не определяет победителя. Остатки, деньги, права и точные замеры проверяются сервером; совместимые действия применяются, конфликтующие требуют сохранённой формы, показа последствий и подтверждения либо формы «Что есть сейчас».
- Для неразрешимых конфликтов показать пользователю ручной выбор версии.
- Если слияние невозможно, хранить обе версии с пометкой конфликта до решения.

<a id="185-локальная-защита-и-кэш"></a>

## 18.5. Локальная защита и кэш

<!-- /migration:source-1151 -->

<a id="source-1153"></a>
<!-- migration:source-1153 -->

Пароль пользователя локально не хранить. Для Web/PWA основной online-сеанс использовать через `HttpOnly`, `Secure`, подходящий `SameSite` cookie с CSRF-защитой и ротацией; доступные JavaScript токены длительной авторизации не хранить. IndexedDB/Cache Storage минимизировать, разделять по пользователю, очищать при logout/отзыве и защищать CSP/XSS-мерами. TLS, шифрование диска/объектного хранилища и field-level encryption для выбранных чувствительных полей являются разными слоями и задаются моделью угроз.
<!-- /migration:source-1153 -->

<a id="source-1155"></a>
<!-- migration:source-1155 -->

Личный кэш хранить до 30 дней. Семейный доступ подтверждается подписанным сервером `validated_until`, а не часами устройства. Семейные данные могут физически оставаться в зашифрованном кэше в пределах retention, но после `validated_until` (не более 24 часов и не дольше подписки+страховки) UI закрывает их до повторной проверки прав. При известном отзыве доступа семейный кэш закрывается немедленно и удаляется по политике очистки. Неиспользуемый кэш очищать фоново раз в неделю. На `/settings/offline` дать действие «Очистить локальные данные»: перед выполнением обязательно показать подтверждение с прямым предупреждением, что ранее загруженная информация исчезнет с текущего устройства и станет недоступна без интернета. Очистку выполнять только после явного согласия пользователя; она удаляет весь локальный кэш текущего аккаунта на этом устройстве, но не изменяет данные на сервере.

## 28.12. История, конкурентность и офлайн

<!-- /migration:source-2306 -->

<a id="source-2308"></a>
<!-- migration:source-2308 -->

- История различает поступление, приготовление, расход, перемещение, корректировку и откат; хранит автора, effective_at, recorded_at, дельты и связи. Одно действие — одна раскрываемая запись. Расход не равен съеденному.
- Запись задним числом проверяет последующую инвентаризацию и спрашивает, уже ли расход учтён. Корректировки компенсирующие, исторические версии не переписываются. Сервер повторно проверяет права/остатки; idempotency предотвращает двойное действие.
- Общий MVP реализует офлайн-возможности §18.1 по мере выпуска Free, Plus и Pro: приготовление/таймеры, загруженные рецепты и списки, личный дневник Pro, ручные покупки и личный CRUD рецептов. Любое локальное изменение имеет честный статус «сохранено на устройстве, ещё не отправлено». AI, платежи, публикация, модерация и требующие актуального сервера действия offline не считаются выполненными. После потерянного ответа сначала проверять результат.
- Семейный offline действует по подписанному сервером `validated_until` — максимум 24 часа после проверки и не дольше подписки+страховки; часы устройства срок не продлевают. При sync права проверяются заново; закрытые семейные изменения не переносятся в личное, собственный ввод сохраняется отдельно, семейный кэш закрывается при отзыве. Личный кэш может физически храниться дольше, но это не продлевает семейную авторизацию.
