## 8.1. Доступные действия

<!-- /migration:source-609 -->

<a id="source-611"></a>
<!-- migration:source-611 -->

Пользователь может:
<!-- /migration:source-611 -->

<a id="source-613"></a>

## 8.2. Минимальные поля рецепта

<!-- /migration:source-622 -->

<a id="source-624"></a>
<!-- migration:source-624 -->

Для отправки на публикацию обязательны:
<!-- /migration:source-624 -->

<a id="source-626"></a>
<!-- migration:source-626 -->

- название;
- ингредиенты;
- шаги приготовления.

<!-- /migration:source-626 -->

<a id="source-630"></a>
<!-- migration:source-630 -->

Фото и КБЖУ необязательны, но рекомендуются. Неполные сведения об аллергенах не считаются доказательством безопасности: рецепт может участвовать в персональной выдаче без изменения score, но карточка обязана показать предупреждение. В режиме `hide` автоматически исключается только подтверждённый статус `contains`; `may_contain`, `unknown` и отсутствие полноты остаются видимыми предупреждениями.

Аллергены рецепта выводятся из двух раздельных источников: explicit composition evidence конкретной версии состава и управляемых администратором mappings для ingredient/variant/SKU. Mapping не переписывает и не понижает прямое evidence, но также не доказывает полноту по остальным аллергенам: unknown снимается только явным `compositionComplete` версии состава. Карточка возвращает provenance, связанные позиции рецепта, icon projection и unknown ingredients; отсутствие данных не означает безопасность. Пользователь может отправить в поддержку только выбранные сервером unknown-позиции без передачи личных allergen preferences.

## 8.4. Пересчёты

<!-- /migration:source-650 -->

<a id="source-652"></a>
<!-- migration:source-652 -->

- При изменении количества, порций, замен, добавлении или исключении ингредиента автоматически пересчитывать КБЖУ, если у всех необходимых ингредиентов есть данные.
- Если полный перерасчёт невозможен, показывать КБЖУ исходного рецепта с явной пометкой «Данные базового рецепта — изменения не учтены», перечислять непокрытые ингредиенты и не выдавать это число за КБЖУ модифицированного блюда.
- Стоимость модифицированного рецепта пересчитывается на основании доступных примерных медианных цен продуктов.
- Время показывать диапазоном; факторы: число порций, способ приготовления, замены и изменение шагов.

## 9.1. Общий счётчик

<!-- /migration:source-665 -->

<a id="source-667"></a>
<!-- migration:source-667 -->

- Один общий счётчик на активное приготовление рецепта.
- Стартует при запуске пошагового режима.
- Показывает прошедшее время.
- Работает независимо от локального таймера.
- Используется как источник фактической длительности приготовления.

<!-- /migration:source-667 -->

<a id="source-673"></a>
<!-- migration:source-673 -->

<a id="92-локальный-таймер-шага"></a>

## 9.2. Локальный таймер шага

<!-- /migration:source-673 -->

<a id="source-675"></a>
<!-- migration:source-675 -->

- Запускается из текущего шага с длительным действием: варка, запекание, маринование, охлаждение, отдых теста и т. п.
- Время по умолчанию берётся из структуры рецепта, до запуска его можно изменить.
- В MVP допускается один активный локальный таймер.
- Локальный таймер не отмечает шаг выполненным автоматически.
- Пользователь может поставить таймер на паузу, возобновить, сбросить, добавить или уменьшить время.
- Быстрые действия: `+1 мин`, `+5 мин`, `+10 мин`, `-1 мин`, `-5 мин`; также доступен произвольный ввод.

<a id="96-незавершённое-приготовление"></a>

## 9.6. Незавершённое приготовление

<!-- /migration:source-705 -->

<a id="source-707"></a>
<!-- migration:source-707 -->

- Незавершённый процесс сохраняется как черновик.
- Напомнить через 2 дня; повторить ещё через 2 дня.
- Архивировать черновик на шестой день от начала приготовления — через два дня после номинального срока второго напоминания. Перенос доставки из-за тихих часов не продлевает срок хранения черновика.
- Через 1 месяц скрыть архивный черновик из обычного интерфейса. Физическое удаление черновика и связанных временных данных выполняется только по утверждённой retention-политике; история фактических движений не удаляется вместе с черновиком.
- Пользователь может отключить эти напоминания.
- Тихие часы напоминаний — 22:00–09:00 по локальному часовому поясу пользователя. Попавшее в этот интервал напоминание переносится на ближайшие 09:00; в БД даты хранятся в UTC. Без известного часового пояса доставку не планировать до его настройки.
- После сознательной отмены приготовления не напоминать.

## 10.2. Методика

<!-- /migration:source-730 -->

<a id="source-732"></a>
<!-- migration:source-732 -->

Подозрительное измерение сохраняется и может быть возвращено в расчёт после проверки.

## 28.7. Рецепты, приготовление и остатки

<!-- /migration:source-2262 -->

<a id="source-2264"></a>
<!-- migration:source-2264 -->

- Авторство рецепта всегда закреплено за создавшим его пользователем. Семейная доступность — отдельное свойство, по умолчанию рецепт доступен семье при членстве; семья и её владелец не становятся автором. Выбор личного режима ограничивает доступ автором, но не меняет авторство. Само предоставление семейного доступа не выдаёт новых прав редактирования и не меняет существующие авторские правила. Новый рецепт — черновик в выбранной области по §4.4, семейной по умолчанию при членстве. Искать похожий и предлагать: тот же, другой или вариация способа; личный черновик не удалять. Разовые замены по умолчанию относятся только к приготовлению; «Сохранить мой вариант» создаёт вариацию в выбранной области, «Предложить сообществу» — заявку.
- «Начать готовить» показывает пересчёт, замены, оборудование и ограничения, но не списывает. При нехватке: изменить отдельный ингредиент, заменить, пропорционально уменьшить либо «Приготовим как есть». Температуру/время слепо не масштабировать.
- «Готово» одной сводкой подтверждает фактические продукты/источники, количества, выход и размещение; повторное нажатие идемпотентно. Каждое приготовление — отдельная партия со snapshot версии рецепта, товаров, состава, замен и точности. Разные приготовления лишь визуально группируются.
- Партия делится по местам/состояниям; производное блюдо расходует готовую часть и новые ингредиенты, не первичные продукты повторно. Один основной остаток, дополнительные единицы связаны пересчётом. Выбранное для готовки/плана число порций — минимум 1; число полных порций из фактического выхода округляется вниз и может быть 0, физический остаток сохраняется. Фактический замер приоритетнее оценки.
- «Продолжу позже» не списывает; «Зафиксировать использованное» создаёт промежуточную заготовку. «Не удалось — выбросили» списывает фактическое, но не создаёт доступный запас или дневник; повтор — новая попытка. Причина необязательна и приватна до отдельной публикации.
- Готовую еду без рецепта можно добавить вне каталога: обязательно только название; состав, КБЖУ, количество, источник и даты необязательны, unknown не ноль.
- Оценка 1–5 только после готовки, один неизменяемый голос пользователя на рецепт, вариация отдельно. До окончательной фиксации требуется отдельное подтверждение или короткая возможность отменить случайный выбор; после фиксации оценка не редактируется. Комментарий можно редактировать с отметкой и удалять/скрывать по правилам; ответы вызывают уведомление. Фактическое время подтверждается пользователем, публично показывается медиана по сопоставимой версии/способу/масштабу и размер выборки.
