# Первый администратор для разработки и тестов

## Самый быстрый вариант: демонстрационная админка

1. Запустите `meal_admin` в режиме `mock`.
2. Откройте `http://localhost:3002/auth`.
3. Введите логин `admin` и пароль `1`.
4. Админка покажет ключ для приложения-аутентификатора. Добавьте его в любое приложение, которое создаёт шестизначные одноразовые коды.
5. Введите текущий код.
6. Сохраните десять резервных кодов и подтвердите, что они сохранены.

Если тестовый ключ потерян, удалите данные сайта `localhost:3002` в настройках браузера и войдите заново. Это удалит только демонстрационные данные в этом браузере.

## Реальная development/test-база

Сначала создайте обычный аккаунт через основное приложение. В поле «Логин» укажите именно `admin`: дальнейшие команды используют это значение.

1. Откройте `http://localhost:3000/register` и зарегистрируйте аккаунт с логином `admin`.
2. Откройте локальный почтовый ящик `http://localhost:3000/dev/mailbox`.
3. Найдите самое новое письмо для указанного адреса и перейдите по ссылке подтверждения.
4. Убедитесь, что аккаунт активирован, и только после этого назначайте роль.

Локальный почтовый ящик используется только в development-режиме: внешняя почтовая служба для этого шага не нужна.

### 1. Безопасная предварительная проверка

В папке `meal_backend` выполните:

```powershell
npm run build
npm run admin:bootstrap -- --login admin --reason "Первый локальный администратор"
```

Команда проверит аккаунт и базу, но ничего не изменит. Ожидаемый статус — `planned`. Если пользователь не найден или не подтверждён, вернитесь к регистрации и локальному почтовому ящику. Если статус `already_completed`, этот пользователь уже является первым администратором.

### 2. Назначение роли

Убедитесь, что используется именно development/test-база. Затем в том же окне PowerShell:

```powershell
$env:ADMIN_BOOTSTRAP_ENABLED='true'
npm run admin:bootstrap -- --login admin --confirm-login admin --reason "Первый локальный администратор" --execute
Remove-Item Env:ADMIN_BOOTSTRAP_ENABLED
```

Ожидаемый статус — `completed`. Команда:

- работает только в `development` и `test`;
- отказывается продолжать, если уже есть другой действующий администратор;
- не принимает и не выводит пароль;
- назначает роль и записывает событие в историю одной операцией;
- при точном повторе не создаёт вторую роль.

### 3. Первый вход

1. Откройте `http://localhost:3002/auth`.
2. Введите логин и пароль созданного аккаунта.
3. Добавьте показанный ключ в приложение-аутентификатор.
4. Введите шестизначный код.
5. Сохраните десять резервных кодов.

Без сохранённых резервных кодов не продолжайте тестирование критичных действий.

## Если потерян доступ к приложению-аутентификатору

Сначала выполните только проверку:

```powershell
npm run admin:mfa-recover -- --login admin --reason "Утерян доступ к приложению-аутентификатору"
```

Фактическое восстановление изменяет данные и выполняется только после отдельного подтверждения владельца базы. После восстановления следующий вход предложит настроить новый ключ.
